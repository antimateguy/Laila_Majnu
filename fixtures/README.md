# Fixtures

Everything here is generated by `generator/gen.py` from `generator/seed.json`; never edit it by hand.

```bash
python fixtures/generator/gen.py                              # regenerate
python -m unittest discover -s fixtures/generator             # invariants + byte-identical regeneration
```

CI regenerates and fails on any `git diff` under `fixtures/`. `.gitattributes` marks the synthetic and expected trees `-text`, so git never rewrites their line endings.

## Layout

| Path | What |
| --- | --- |
| `synthetic/whatsapp/{android,ios}/<id>/_chat.txt` | WhatsApp exports |
| `synthetic/instagram/<id>/message_N.json` | Instagram DM threads (mojibake, newest first, split) |
| `synthetic/zips/` | The same exports in their containers, for the web unzip path |
| `expected/<id>.json` | Ground truth per fixture: parse context, expected `ParseCode`, participants, every message |
| `pii/labelled_in.jsonl` | Labelled Indian PII set for the sanitizer recall bar |
| `manifest.json` | Seed, the canary string, fixture list and participant names (for the e2e canary test) |

## Expected-output contract

- `participants` are in `ParticipantId` order (first appearance, chronological), system lines excluded; `self_id` is the user's id.
- `sender: null` means a system line (`kSystem`).
- `ts_utc_ms` is truncated to the export's precision: minutes (Android), seconds (iOS), milliseconds (Instagram).
- `text` is the body without header, with `\r\n` inside multi-line messages normalised to `\n`, the edit marker removed (`edited: true`), and an iOS leading U+200E removed. Media and deleted placeholders have `text: ""` and `kind` `Media` / `Deleted`.
- `context.transitions` is the table the web worker builds from `Intl`: `from_local_min` is the local wall-clock minute (read as UTC) where `offset_min` starts. No fixture message falls in a DST fall-back overlap, which the parser cannot resolve.

## Fixtures

| id | Exercises |
| --- | --- |
| `android_12h_dmy` | Indian-English Android: `dd/mm/yy, h:mm am - `, plain space, lowercase am/pm |
| `android_12h_mdy` | US Android: `m/d/yy, h:mm PM - ` with U+202F |
| `android_24h_dmy` | 4-digit year `dd/mm/yyyy, HH:mm - ` |
| `android_24h_mdy` | `m/d/yy, HH:mm - ` |
| `ios_{12h,24h}_{dmy,mdy}` | `[d/m/yy, hh:mm:ss PM] ` with U+202F, U+200E markers, CRLF line endings |
| `ios_24h_mdy` | Other side saved only as a phone number (`+91 98765 01234`) |
| `android_24h_dmy_london_dst` | Europe/London, crosses the 25 Oct 2026 BST→GMT change |
| `android_ambiguous_date_order` | Every date field ≤ 12 and both readings monotonic → `AmbiguousDateOrder` |
| `android_group_3p` | Three participants → `GroupChatRejected` |
| `ios_trailer_small` | Under 300 messages and 14 days → trailer mode |
| `instagram_split_mojibake` | Two `message_N.json` parts, newest first, Latin-1 mojibake, reactions, photo, share |
| `instagram_single` | One part |

Every fixture contains the canary once, Hinglish and English lines, emoji, a third-party first name, a phone number, an email and a URL.

## Assumptions to verify against real exports — TODO(fixture-real)

None of these come from real files. Each needs checking against the ~30 anonymized real exports the LLD calls for:

1. Android uses LF and iOS uses CRLF line endings.
2. Android 12h in Indian English uses a plain space before lowercase `am`/`pm`; US Android uses U+202F before `AM`/`PM`.
3. Day/month are zero-padded in DMY locales and not in MDY; some DMY locales use 4-digit years.
4. System-string wording: the encryption notice, `<Media omitted>`, `image omitted`, `This message was deleted` / `You deleted this message`, `<This message was edited>`.
5. iOS attributes the encryption notice to the chat name, prefixed with U+200E.
6. Instagram record fields (`photos`, `share.link`, `is_geoblocked_for_viewer`, the "sent an attachment." content) and the zip path `your_instagram_activity/messages/inbox/<thread>/`.
7. Instagram reaction emoji are a single code point (`❤` without U+FE0F).
